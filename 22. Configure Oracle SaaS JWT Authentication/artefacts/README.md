# Artefacts — Oracle SaaS JWT Authentication (sample)

These are sample/demo artefacts generated by `generate_jwt.sh`, matching the steps in `../README.md`. They illustrate the file shapes and JWT structure — they are **not** real credentials for any system.

| File | Description |
|---|---|
| `generate_jwt.sh` | Regenerates everything below. Edit `ISSUER` / `PRINCIPAL` to match your Trusted Issuer and Fusion username. |
| `private.key` | Sample RSA private key (Step 1a). **Never commit or share a real private key** — replace this with your own, kept outside version control. |
| `publickey.cer` | Sample self-signed X.509 certificate (Step 1b). Upload the real one to **Security Console > API Authentication** in Oracle Fusion (Step 2). |
| `header.json` | Sample decoded JWT header (Step 3.1), including the `x5t` fingerprint of `publickey.cer`. |
| `payload.json` | Sample decoded JWT payload/claims (Step 3.2). |
| `sample_jwt_token.txt` | The full signed JWT (Step 3.3) — use as `Authorization: Bearer <token>` when calling a Fusion REST/SOAP API (Step 4). |

To regenerate with fresh keys and a new token:

```bash
./generate_jwt.sh
```

> **Security note:** the `private.key` in this folder is a throwaway demo key committed only for illustration. For a real integration, generate your own key pair, keep the private key out of source control, and upload only the public certificate to Oracle Fusion.
